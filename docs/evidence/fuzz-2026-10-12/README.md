## Findings

F1, fixed (impulse-core, threshold_public). The FROST point decoder accepts SEC1 prefixes other than 2 and 3 and reads them as a
parity, so one round-1 package, group key or commitment had several byte encodings, and decode then encode did not round-trip.
Every public point decoder in `threshold/encoding.rs` now refuses such a prefix as `THRESHOLD_ENCODING`. Regression test:
`threshold::tests::public_encodings_refuse_a_point_prefix_other_than_2_or_3`. Crash input: `artifacts/crash-c516...`.

F2, open (kaspa-rpc-core Borsh readers, pinned rev a41a333, reached from cli_rpc_wire). `Vec::with_capacity` is sized from an
unchecked u64 length prefix, so a hostile or compromised node can make the CLI abort with a failed allocation
(libFuzzer: `malloc(893353197360)`). Input: `artifacts/oom-08ae...`. Not fixable in this repository without a pin bump or
a patched client; the harness caps allocations at 1 GiB and treats a refused allocation as expected.

F3, open (same crate set, `addresses/src/lib.rs:232`). `Address::new` asserts the payload length for a non-test prefix, and the
Borsh reader of a node response builds addresses through it, so a hostile node can panic the CLI. Input:
`artifacts/crash-1880...`. Same limitation as F2; the harness swallows only that assert.
Impact of F2 and F3: the CLI process stops; no key material is involved and nothing is signed or submitted by it.
